## Why

Operators can silence external log delivery but cannot dial down what the connector writes to the ISC host log. Today `LogService` always builds every message — formatting strings and capturing stack-trace caller origin — and relies on the SDK logger to drop lines below the effective level, while the platform exposes only a boolean debug toggle (info or debug). There is no Error/Warn/Info choice, so noisy aggregations cannot be quieted without turning everything off, and below-level work is still built on every call. Adding a first-class **Log level** makes verbosity a deliberate setting and lets the connector skip below-level work entirely.

## What Changes

**Advanced Settings → Log Settings**
- From: no host-log level control; only the platform `spConnDebugLoggingEnabled` boolean (info/debug) exists.
- To: a new **Log Settings** section with a **Log level** radio — Error / Warn / Info / Debug — default **Info**, stored as `logLevel`.
- Reason: give operators an explicit verbosity dial between "everything" and "nothing".
- Impact: additive UI section; non-breaking. New `logLevel` key in connector-spec initial values.

**Level gate in `LogService`**
- From: `log()` always formats the message, conditionally captures caller origin, calls the SDK logger for every level, and tracks warn/error issues.
- To: `log()`, `assert()`, and `crash()` skip messages below the configured **Log level** *before* building the message or capturing caller origin. Warn/error aggregation issue tracking is unchanged so reports stay accurate.
- Reason: honoring the level early removes avoidable work as well as avoidable output.
- Impact: observable output at and above the level is unchanged; behavior below the level changes from "built then discarded" to "not built".

**Precedence with the platform debug toggle**
- From: explicit `logLevel` (never set by the UI) > `spConnDebugLoggingEnabled` > `info`.
- To: `spConnDebugLoggingEnabled === true` forces `debug`; otherwise the **Log level** setting applies (default `info`).
- Reason: keep the platform debug escape hatch working now that the setting is always defined.
- Impact: non-breaking for existing configs; debug toggle still wins.

**External logging interaction**
- From: external delivery filtered solely by **External logging level**; messages below the host level were still built.
- To: host emission is gated by **Log level**; external delivery stays gated by **External logging level**; message construction is skipped only when neither active sink wants it.
- Reason: quieten the host stream without regressing external-debug setups.
- Impact: non-breaking; external behavior preserved.

## Capabilities

### New Capabilities

(none)

### Modified Capabilities

- `log-service`: add a **Log level** contract — Log Settings (`logLevel`, Error/Warn/Info/Debug, default Info), host emission gated before message construction, debug-toggle precedence, issue-summary independence, and external-delivery interaction.
- `ubiquitous-language`: add **Log Settings** and **Log level** canonical terms; keep **External logging level** distinct.

## Impact

- **Code**: new `src/data/config/settings/logSettings.ts`; `src/data/config/readConfig.ts` (settings pipeline), `src/data/config/defaults.ts` (initial values + runtime defaults), `src/model/config.ts` (`LogSettingsSection` on `AdvancedSettingsMenu`), `src/services/logService/logService.ts` (level gate + precedence).
- **Config**: `connector-spec.json` — new **Log Settings** section under Advanced Settings with the `logLevel` radio; `sourceConfigInitialValues.logLevel`; `scripts/connector-spec-help-lib.cjs` (section help entry) so `npm run lint` passes.
- **Specs**: deltas for `log-service` and `ubiquitous-language`.
- **Docs**: `docs/reference/observability.md` and `docs/use-guides/operation/monitor-aggregation-progress.md` (Log level vs External logging level), `docs/glossary.md` (mirror new terms); `docs/configuration/advanced.md` regenerated by `npm run docs:prepare`. CHANGELOG entry.
- **APIs/contracts**: connector-spec gains one optional radio field; no runtime API or schema changes. Non-breaking.
